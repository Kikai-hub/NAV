## Про поворот персонажа к камере

Ты попросил, чтобы персонаж всегда смотрел туда, куда смотрит камера.
**Это уже реализовано** и работает независимо от анимаций:
`PlayerMotor.Update()` каждый кадр ставит `transform.rotation` тела
персонажа равным yaw камеры (`_cameraTransform.eulerAngles.y`) — то
есть тело **всегда** развёрнуто ровно в направлении взгляда камеры, вне
зависимости от того, в какую сторону движется игрок (W/A/S/D). Это и
даёт "странфовое" движение: если жать S, персонаж не разворачивается
спиной, а идёт назад лицом всё туда же, куда смотрит камера — под это
как раз и сделан 8-направленный набор анимаций (Forward/Backward/
Left/Right/диагонали), см. ниже.

Про твою фразу в скобках ("только когда она смотрит за него он смотрит
в противоположную сторону") — честно, не до конца понял этот случай:
в текущей камере (`ThirdPersonCameraController`) нет столкновений со
стенами/переключения "камера спереди" — камера всегда орбитит вокруг
`CameraTarget` на фиксированной дистанции. Если ты имел в виду именно
этот текущий режим (тело всегда = направление камеры, без исключений)
— ничего менять не нужно, всё уже так. Если ты имел в виду что-то
конкретное (например, отдельный случай для движения назад, или для
камеры, упирающейся в стену) — опиши подробнее, и я это добавлю
отдельно; сама анимационная система ниже от этого не зависит и будет
работать в любом случае.

## План

1.  `PlayerAnimator.cs` (уже добавлен, код) —
    `Assets/NAV/Scripts/Presentation/Animation/PlayerAnimator.cs`.
    Каждый кадр читает `PlayerInputHandler.MoveInput` (уже в системе
    координат тела персонажа, т.к. тело всегда развёрнуто как камера
    — см. выше, доп. преобразований не нужно) и пишет в Animator
    параметры `MoveX`/`MoveY` через **демпфированный**
    `Animator.SetFloat(name, value, dampTime, deltaTime)` — это и даёт
    плавность (параметр плавно "доезжает" до нужного значения, а не
    прыгает), плюс `IsSprinting`/`Grounded` из `PlayerMotor`.
2.  Animator Controller с одним **2D Freeform Directional Blend
    Tree** ("Locomotion") — Idle в центре, 8 направлений ходьбы вокруг
    — все анимации ходьбы/страйфа/движения назад объединены в ОДНО
    плавное 2D-пространство, управляемое `MoveX`/`MoveY`. Это и есть
    "чтобы анимации были объединены и смена направления смотрелась
    естественно" — стандартный приём для camera-locked персонажа
    (Valheim, кстати, использует то же самое).
3.  Второй Blend Tree ("Sprint Locomotion") на спринт-клипах,
    переключение по `IsSprinting` с коротким кроссфейдом.
4.  Простое состояние `Jump` (клип `Fall01`) по `Grounded` — без
    отдельных фаз "разбег/приземление", это не то, о чём ты просил, но
    без него персонаж будет "зависать" в позе ходьбы в воздухе, что
    выглядело бы хуже.

## Root Motion --- используем клипы БЕЗ [RM]

У части анимаций есть версии с `[RM]` в названии (Root Motion — сама
анимация двигает объект в мире) и без (только поза, движение полностью
на твоём скрипте `PlayerMotor`/`CharacterController`). **Используем
версии без `[RM]`** — персонаж и так полностью управляется
`CharacterController` в коде; если включить Root Motion поверх этого,
получится "двойное" движение (скольжение ног, рассинхрон). Animator
Controller ниже собирается только из клипов без `[RM]` в имени.

------------------------------------------------------------------------

## Шаг 1. Разместить модель под Player

1.  В Hierarchy разверни `Player`.
2.  Перетащи `Assets/NAV/Prefabs/Player/HumanDummy_F Red.prefab` **в
    Player** (сделай его дочерним объектом Player).
3.  У дочернего объекта (модели) выставь **Position: (0, 0, 0)**,
    **Rotation: (0, 0, 0)** — `CharacterController` на Player имеет
    Height 1.8 / Radius 0.3 / Center (0, 0.9, 0), то есть **ступни на
    уровне Y=0 у самого Player** — большинство таких моделей уже
    авторены так, что их собственный корень тоже стоит на полу, так
    что (0,0,0) обычно совпадает. Если после Play персонаж окажется
    "в земле" или "парит" — подвинь только модель (не Player/
    CharacterController) по Y, пока ступни не встанут на пол.
4.  Если рост модели визуально сильно не совпадает с капсулой (1.8 м)
    — выставь модели одинаковый **Scale** по всем осям (например,
    `(1.05, 1.05, 1.05)`), не растягивая по одной оси.

## Шаг 2. Создать Animator Controller

1.  В окне **Project**: `Assets/NAV/` → создай папку `Animations`
    (если её ещё нет), внутри — `Assets/NAV/Animations/Player/`.
2.  Правой кнопкой в этой папке → **Create → Animator Controller**.
    Назови `PlayerAnimatorController`.
3.  Двойной клик — откроется окно **Animator**.

## Шаг 3. Добавить параметры

В окне Animator, вкладка **Parameters** (обычно слева), нажми **+**
четыре раза и добавь:

-   `MoveX` — **Float**
-   `MoveY` — **Float**
-   `IsSprinting` — **Bool**
-   `Grounded` — **Bool** (по умолчанию можно оставить `false`, при
    Play скрипт быстро выставит правильное значение)

## Шаг 4. Locomotion Blend Tree

1.  Правой кнопкой в пустом месте графа Animator → **Create State →
    From New Blend Tree**. Назови новое состояние `Locomotion`.
2.  Двойной клик по `Locomotion` — зайдёшь "внутрь" бленд-дерева.
3.  Выдели сам узел Blend Tree (в Inspector) → **Blend Type: 2D
    Freeform Directional**. В полях **Parameters** укажи `MoveX` и
    `MoveY` (X → MoveX, Y → MoveY).
4.  В таблице **Motion** нажми **+ → Add Motion Field** девять раз (1
    Idle + 8 направлений), и для каждого перетащи соответствующий клип
    (все — из `Assets/Kevin Iglesias/Human Animations/Animations/
    Female/`), затем вручную выставь его **Pos X**/**Pos Y** в той же
    строке таблицы:

    | Клип (Idles/Movement/Walk, без `[RM]`) | Pos X | Pos Y |
    |---|---|---|
    | `Idles/HumanF@Idle01` | 0 | 0 |
    | `Movement/Walk/HumanF@Walk01_Forward` | 0 | 1 |
    | `Movement/Walk/HumanF@Walk01_Backward` | 0 | -1 |
    | `Movement/Walk/HumanF@Walk01_Left` | -1 | 0 |
    | `Movement/Walk/HumanF@Walk01_Right` | 1 | 0 |
    | `Movement/Walk/HumanF@Walk01_ForwardLeft` | -0.7 | 0.7 |
    | `Movement/Walk/HumanF@Walk01_ForwardRight` | 0.7 | 0.7 |
    | `Movement/Walk/HumanF@Walk01_BackwardLeft` | -0.7 | -0.7 |
    | `Movement/Walk/HumanF@Walk01_BackwardRight` | 0.7 | -0.7 |

5.  Выйди из бленд-дерева (стрелка "назад" вверху окна Animator).
6.  Правой кнопкой на `Locomotion` → **Set as Layer Default State**
    (должно уже стоять по умолчанию как первое созданное состояние —
    проверь, что он оранжевый).

## Шаг 5. Sprint Blend Tree

1.  Так же: правой кнопкой в графе → **Create State → From New Blend
    Tree**, назови `Sprint Locomotion`.
2.  Зайди внутрь, **Blend Type: 2D Freeform Directional**, Parameters
    `MoveX`/`MoveY`.
3.  Добавь **восемь** motion fields (без Idle — в спринт мы попадаем
    только уже двигаясь):

    | Клип | Pos X | Pos Y |
    |---|---|---|
    | `Movement/Sprint/HumanF@Sprint01_Forward` | 0 | 1 |
    | `Movement/Run/HumanF@Run01_Backward` | 0 | -1 |
    | `Movement/Sprint/HumanF@Sprint01_Left` | -1 | 0 |
    | `Movement/Sprint/HumanF@Sprint01_Right` | 1 | 0 |
    | `Movement/Sprint/HumanF@Sprint01_ForwardLeft` | -0.7 | 0.7 |
    | `Movement/Sprint/HumanF@Sprint01_ForwardRight` | 0.7 | 0.7 |
    | `Movement/Run/HumanF@Run01_BackwardLeft` | -0.7 | -0.7 |
    | `Movement/Run/HumanF@Run01_BackwardRight` | 0.7 | -0.7 |

    (У пакета нет спринта назад/по диагонали назад — временно
    переиспользую клипы бега `Run` для этих трёх позиций, это
    компромисс, не идеал; замени на нормальные клипы, если найдёшь/
    сделаешь подходящие, ничего в коде менять не придётся.)
4.  Выйди из бленд-дерева.

## Шаг 6. Переходы Locomotion ↔ Sprint

1.  Правой кнопкой на `Locomotion` → **Make Transition** → кликни на
    `Sprint Locomotion`. Выдели стрелку перехода, в Inspector:
    -   **Has Exit Time**: выключи (снять галочку).
    -   **Transition Duration**: `0.15` (небольшой кроссфейд, чтобы не
        было рывка).
    -   **Conditions**: **+** → `IsSprinting` → `true`.
2.  Аналогично сделай обратный переход: `Sprint Locomotion` →
    `Locomotion`, те же настройки, условие `IsSprinting` → `false`.

## Шаг 7. Простой Jump (по Grounded)

1.  Правой кнопкой в графе → **Create State → Empty**, назови `Jump`.
2.  В Inspector у `Jump` в поле **Motion** перетащи
    `Assets/Kevin Iglesias/Human Animations/Animations/Female/
    Movement/Jump/HumanF@Fall01.fbx`.
3.  Правой кнопкой на пустом месте графа → **Create Transition** от
    **Any State** к `Jump`: выдели `Any State`, **Make Transition** →
    клик на `Jump`. У перехода: **Has Exit Time** выкл, **Duration**
    `0.1`, условие `Grounded` → `false`.
4.  Обратный переход `Jump` → `Locomotion`: **Has Exit Time** выкл,
    **Duration** `0.15`, условие `Grounded` → `true`.

## Шаг 8. Назначить контроллер модели и добавить PlayerAnimator

`PlayerAnimator` требует компонент `Animator` **на том же объекте** —
а `Animator` стоит на дочерней модели, не на `Player`, поэтому весь
этот шаг делается на модели, не на `Player`.

1.  Выдели дочернюю модель (`HumanDummy_F Red`) под Player в Hierarchy.
2.  На её компоненте **Animator**:
    -   **Controller** — перетащи `PlayerAnimatorController.controller`.
    -   **Avatar** — должен быть уже проставлен автоматически (аватар
        из `HumanCharacterDummy_F.fbx`); если пусто — перетащи явно.
    -   **Apply Root Motion** — **выключи** (см. раздел про Root
        Motion выше).
3.  На той же модели: Add Component → добавь `PlayerAnimator`
    (namespace `NAV.Presentation.Animation`).
4.  Заполни поля:
    -   **Input Handler** — объект **Player** (родитель).
    -   **Motor** — объект **Player** (там же `PlayerMotor`).

## Шаг 9. Проверка

1.  Нажми **Play**.
2.  Стоя на месте — персонаж должен проигрывать Idle.
3.  W/A/S/D по отдельности — персонаж должен идти вперёд/вбок/назад,
    оставаясь развёрнутым туда же, куда смотрит камера (не
    разворачиваясь корпусом к направлению движения).
4.  Задай диагональ (например W+D одновременно) — переход должен
    выглядеть как плавное смешение между Forward и Right, а не
    дёрганая смена одной анимации на другую.
5.  Резко смени направление (например, отпусти W, зажми S) — не должно
    быть рывка/попа, анимация должна плавно "довернуть" за счёт
    демпфирования в `PlayerAnimator`.
6.  Зажми Shift и двигайся — должен включиться спринт-блендтри (более
    быстрый бег), с плавным кроссфейдом при входе/выходе.
7.  Прыгни (Space) — в воздухе должна проиграться поза падения вместо
    зависшей позы ходьбы, на приземлении — плавный возврат в
    Locomotion.
8.  Если что-то выглядит не так (рывки, персонаж "плывёт" ногами,
    неправильная нога у клипа и т.п.) — опиши/пришли видео, разберёмся
    прицельно.
