### 7.3. Создать тестовый объект для подбора

4.  Проверь, что есть **Sphere Collider** (добавляется автоматически).
5.  Add Component → добавь `ItemPickup`
    (namespace `NAV.Gameplay.Items`).

    `Assets/NAV/ScriptableObjects/Items/Wood.asset`.

### 7.4. Проверка

1.  Нажми **Play**.
2.  Подойди к сфере `TestPickup_Wood`, наведи на неё камеру.
3.  В HUD должна появиться строка `Interact: Pick up Wood`.
4.  Зажми **E** (удержание, как и раньше).
5.  Ожидаемый результат:
    -   сфера должна исчезнуть (если весь стак поместился в инвентарь);
    -   в Console — сообщение вида
        `Player picked up 5x Wood (now has 5).`;
    -   в HUD строка `Inventory: 1/20 slots used` (один слот занят
        деревом).
6.  Если инвентарь окажется полон (не в этом тесте, а в будущем) —
    сфера должна остаться на месте, а в Console появится сообщение

Как и с кубом — `TestPickup_Wood` и `Wood.asset` можно оставить как
временный тестовый контент до появления настоящей системы добычи

5.  Нажми **I** ещё раз — панель должна закрыться, курсор снова

## Шаг 9. Новое: Gathering, инкремент 1 (ResourceNode)

Первый кусок Gathering (Фаза 3 из `DEVELOPMENT_ROADMAP_v0.1.md`) — узел
ресурса в мире, который можно "бить" несколько раз (E, как обычно),
пока он не даст ресурсы и не исчезнет. Я добавил:

-   `Assets/NAV/Scripts/Gameplay/Items/ResourceNodeDefinition.cs` —
    ScriptableObject-данные узла: какой предмет даёт, сколько за один
    удар, сколько ударов до истощения.
-   `Assets/NAV/Scripts/Gameplay/Items/ResourceNode.cs` — сам узел
    (реализует `IInteractable`, как `ItemPickup`). Каждый Interact() —
    один "удар": добавляет предметы в `PlayerInventory`, уменьшает
    счётчик оставшихся ударов, слегка уменьшает объект в размере
    (временная визуальная обратная связь) и при истощении уничтожает
    объект.

**Сознательно не сделано в этом инкременте** (по роадмапу это отдельные
пункты Gathering, не забытые): требование инструмента (топор/кирка —
пока нет системы Equipment), респавн/сохранение узлов (нужна система
Save), нормальные VFX/звук добычи.

### 9.1. Дать Unity перекомпилировать

Перейди в Unity, дождись компиляции, проверь Console на отсутствие
ошибок.

### 9.2. Создать тестовый ResourceNodeDefinition

2.  Правой кнопкой → **Create → NAV → Items → Resource Node Definition**.

4.  В Inspector заполни:

### 9.3. Создать тестовый объект узла в сцене

### 9.4. Проверка

## Шаг 12. Инвентарь: перекладка панелей, drag-and-drop, вес, выброс предметов, физика

По твоей просьбе (5 пунктов) я переработал инвентарь и панель крафта:

1.  **Панели больше не полноэкранные и не закрывают друг друга.**
    Inventory (**I**) теперь прижат к левому краю экрана, Crafting
    (**K**) — к правому; оба можно держать открытыми одновременно,
    персонаж по центру экрана ничем не закрыт. Курсор
    блокируется/разблокируется теперь централизованно в
    `PlayerInputHandler` (по счётчику открытых панелей), а не в каждой
    панели по отдельности — иначе закрытие одной панели при открытой
    второй ошибочно снова блокировало бы курсор.
2.  **Перетаскивание предметов внутри инвентаря.** Зажми ЛКМ на
    занятом слоте и перетащи на другой слот — предметы поменяются
    местами (если разные) или сложатся в один стак (если одинаковые и
    есть место).
3.  **Вес предметов.** У `ItemDefinition` уже было поле **Weight**
    (кг) — теперь оно реально используется. `PlayerInventory` получил
    поле **Max Weight** (по умолчанию `400`). В панели инвентаря
    появилась строка `Weight: X/400 kg`. Пока суммарный вес меньше
    лимита — всё как обычно; когда вес доходит до лимита (взять
    больше нельзя — `AddItem` сам это ограничивает), персонаж считается
    **перегруженным**: скорость ходьбы падает (множитель `Overload
    Speed Multiplier` на `PlayerMovementStats`, по умолчанию `0.5`), и
    стамина медленно тратится даже стоя на месте (`Overload Drain Per
    Second` на `PlayerStaminaStats`, по умолчанию `5`/сек), пока вес не
    станет меньше лимита.
4.  **Выброс предметов.** Перетащи предмет из инвентаря за пределы
    панели (в игровой мир) и отпусти ЛКМ — предмет выбросится перед
    персонажем как обычный подбираемый предмет.
5.  **Физика предметов.** `ItemPickup` теперь всегда требует
    `Rigidbody` (масса берётся из `Weight` предмета) — и выброшенные, и
    уже существующие в сцене предметы (например, `TestPickup_Wood`)
    падают под гравитацией и физически взаимодействуют с миром, а не
    висят в воздухе.

Для (4) нужен способ создать предмет в мире из чистого кода — для
этого у `ItemDefinition` появилось новое поле **World Prefab**: префаб,
который выбрасывается/спавнится (должен содержать компонент
`ItemPickup`). Без этого поля `DropItem` просто напишет ошибку в
Console и ничего не выбросит — это осознанное решение (см. правило
"Error Handling" в `CLAUDE.md`: не глотать ошибку молча), а не баг.

## Шаг 15. Building, инкремент 2 (правки + примыкание деталей)

По твоему фидбэку с playtest'а Шага 14: детали проваливались наполовину

Правки:

-   **Провал в землю** — исправлено в коде: теперь позиция ставится так,

## Шаг 16. Building: примыкание теперь ещё и разворачивает деталь

поворот оставался ручным (тем, что ты выставил через **R**).

точки `BuildingSnapPoint` теперь используется и её собственный
**Rotation**, не только позиция). Это нужно, чтобы, например, стена,
цепляясь к разным рёбрам фундамента (север/юг — вдоль X, восток/запад —
вдоль Z), каждый раз разворачивалась правильно, а не одинаково для всех
четырёх сторон.

Это значит, что точкам примыкания на фундаменте, которые ты уже
расставил на Шаге 15, нужно доставить поворот (раньше в инструкции был
только Position):

### 16.1. Дать Unity перекомпилировать

Проверь Console — ошибок быть не должно.

### 16.2. Проставить Rotation точкам на WoodFoundation

1.  Открой префаб `WoodFoundation` (двойной клик в
    `Assets/NAV/Prefabs/Build/`).
2.  Выдели `SnapPoint_North` — **Rotation**: оставь `(0, 0, 0)` (уже
    так по умолчанию).
3.  `SnapPoint_South` — **Rotation**: `(0, 0, 0)` (тоже по умолчанию).
4.  `SnapPoint_East` — **Rotation**: поставь `(0, 90, 0)`.
5.  `SnapPoint_West` — **Rotation**: поставь `(0, 90, 0)`.
6.  Выйди из режима редактирования префаба.

Точки на `WoodWall` (`SnapPoint_BottomLeft`/`SnapPoint_BottomRight`)

## Дополнение к Шагу 17. Прицел (crosshair) в центре экрана

По твоему запросу: без отладочного HUD (F1) было непонятно, куда
именно целится игрок — особенно для сбора ресурсов и атаки. Добавил
постоянный прицел в центре экрана, часть того же `PlayerHud`, что и
HP/стамина/хотбар — не отдельная панель.

Прицел — это колечко (`crosshair-ring`) + точка в центре
(`crosshair-dot`), которые меняют цвет в зависимости от того, во что
целится камера **прямо сейчас**. Никакой новой игровой логики для
этого не потребовалось, кроме одного маленького read-only свойства
`PlayerCombat.HasTargetInSight` (тот же raycast, что уже использует
атака, но без урона/кулдауна/траты стамины — просто проверка "жив ли
IDamageable в радиусе оружия прямо на прицеле"). Всё остальное — уже
существующие данные (`PlayerInteractor.CurrentInteractable`,
`PlayerBuilding.CanPlace`/`IsBuildModeActive`).

Приоритет состояний (какое сработает первым):

1.  **Режим строительства** (`PlayerBuilding.IsBuildModeActive`) —
    зелёный, если можно поставить (`CanPlace`), красный, если нет
    (не в радиусе / не хватает ресурсов). Те же по смыслу цвета, что
    у материалов призрака.
2.  Иначе, если камера смотрит на что-то интерактивное
    (`PlayerInteractor.CurrentInteractable` — ресурсная нода, предмет
    на земле, объект рядом с верстаком и т.п.) — золотой (тот же
    акцентный цвет, что у рамок панелей).
3.  Иначе, если в прицеле живая цель в радиусе оружия
    (`PlayerCombat.HasTargetInSight`) — красный.
4.  Иначе — нейтральный кремовый (в тон текста HUD).

Пока открыта любая модальная панель (Inventory/Crafting — курсор
свободен, `PlayerInputHandler.MenuOpen`), прицел полностью скрывается
— целиться курсором мыши в панель ему нечем.

### Требуется обновить существующий объект `PlayerHud`

`PlayerHudController` теперь требует три новых поля (без них компонент
отключит сам себя с ошибкой в Console) — уже заполненным полям
Health/Stamina/Player Inventory это не мешает, просто добавь
недостающее:

    -   **Combat** — объект **Player** (там же `PlayerCombat`).
    -   **Building** — объект **Player** (`PlayerBuilding`) —
        необязательно, но раз он уже есть на Player, можно сразу
        подключить, чтобы прицел красился в режиме стройки.

### Проверка

1.  Нажми **Play**. В центре экрана должно быть видно кольцо с точкой
    (кремового цвета в состоянии покоя).
2.  Наведись на ресурсную ноду/предмет на земле — прицел должен стать

3.  Наведись на `CombatDummy` (или другую цель с `IDamageable`) в

    где он стоял в начале сцены, и восстанавливает HP.
-   `DeathUIController` + `DeathPanel.uxml`/`.uss` (новые,
    `Assets/NAV/Scripts/UI/`) — центральный экран "You Died" с кнопкой
    Respawn, тот же паттерн, что у `PauseUIController`.
-   `CombatDummy` — новое поле **Loot Drops** (список: предмет +
    количество + шанс, тот же тип `ResourceNodeDrop`, что и у
    ресурсных нод): при добивании манекен один раз разбрасывает лут
    вокруг себя физическими подбираемыми предметами. Манекен **не
    исчезает** после смерти (это тестовый объект, не контент) — просто
    перестаёт атаковать и получать урон.

### 22.1. Добавить PlayerDeath на Player

1.  Выдели объект **Player** в Hierarchy.
2.  Add Component → добавь `PlayerDeath` (namespace
    `NAV.Gameplay.Player`).
3.  Заполни поля:
    -   **Input Handler** — объект **Player**.
    -   **Motor** — объект **Player** (там же `PlayerMotor`).
    -   **Combat** — объект **Player** (там же `PlayerCombat`).
    -   **Interactor** — объект **Player** (там же `PlayerInteractor`).
    -   **Building** — объект **Player** (`PlayerBuilding`) —
        необязательно, но раз он уже есть, подключи, чтобы режим
        стройки тоже отключался при смерти.

### 22.2. Создать экран смерти (Death UI)

Точно так же, как делался `PauseUI` (см. Шаг 19):

1.  В Hierarchy: правой кнопкой → **UI Toolkit → UI Document**,
    переименуй в `DeathUI`.
2.  На компоненте **UI Document**:
    -   **Panel Settings** — перетащи существующий
        `NAV_PanelSettings.asset` (тот же, что у остальных панелей).
    -   **Source Asset** — перетащи `DeathPanel.uxml`
        (`Assets/NAV/Scripts/UI/`).
    -   **Sort Order** — `10` (как у `PauseUI`, чтобы экран смерти
        рисовался поверх обычного HUD).
3.  Add Component → добавь `DeathUIController` (namespace `NAV.UI`).
4.  Поле **Player Death** — перетащи объект **Player** (там же
    `PlayerDeath`, добавленный в Шаге 22.1).

### 22.3. Настроить лут манекена

1.  Выдели `CombatDummy_Basic` в SampleScene.
2.  На компоненте `CombatDummy` найди список **Loot Drops**, увеличь
    **Size**, например, до 2:
    -   Элемент 0: **Item** — `Rock.asset`, **Amount** — `2`,
        **Chance** — `1`.
    -   Элемент 1: **Item** — `Wood.asset`, **Amount** — `1`,
        **Chance** — `0.5`.
    -   Это плейсхолдер-контент для проверки механики, не финальный
        лут-дизайн (финальный ростер добычи ещё "Not Yet Decided").
        `Rock`/`Wood` уже имеют `WorldPrefab`, так что дроп сработает
        без дополнительной настройки.

### 22.4. Проверка

1.  Нажми **Play**.
2.  Атакуй `CombatDummy_Basic`, пока не добьёшь (несколько ударов
    Stone Sword). В Console должно появиться `CombatDummy_Basic
    defeated.`, и рядом с манекеном должны физически разлететься
    камни (и, возможно, дерево — по шансу 50%). Подбери их (E) как
    обычные предметы.
3.  Проверь, что манекен после смерти больше не атакует и не
    получает урон (он остаётся в сцене — это ожидаемо).
4.  Проверь смерть игрока: встань рядом с манекеном так, чтобы он
    начал контратаковать, и дай ему набить 100 урона (по умолчанию
    5 урона раз в 2 секунды — можно на время теста понизить **Max
    Health** в `PlayerHealthStats`, чтобы не ждать долго, и вернуть
    обратно после проверки).
5.  При достижении 0 HP:
    -   персонаж перестаёт двигаться/атаковать/взаимодействовать;
    -   курсор освобождается;
    -   появляется экран **You Died** с кнопкой **Respawn**;
    -   строка `Health:` в отладочном HUD (F1) получает пометку
        `(DEAD)`.
6.  Нажми **Respawn** — экран должен закрыться, игрок — вернуться в
    точку старта сцены с полным HP и снова реагировать на управление.
7.  Если что-то не совпало — опиши, что видишь и на каком шаге.
