## Шаг 6. Новое: основа системы предметов (Items Foundation)

Пока тебя не было, я добавил самое начало системы предметов (Фаза 2 из

### 7.1. Добавить PlayerInventory на объект Player

2.  Add Component → добавь `PlayerInventory`

### 7.2. Подключить Inventory к HUD (необязательно, но полезно для проверки)

2.  В поле **Inventory** перетащи объект **Player** (тот же, где добавлен

### 7.3. Создать тестовый объект для подбора

1.  В Hierarchy: правой кнопкой → **3D Object → Sphere** (чтобы визуально
    отличался от куба взаимодействия из Шага 4).
2.  Переименуй в `TestPickup_Wood`.
3.  Поставь рядом с игроком (например, `Position: (-3, 0.5, 3)`).
4.  Проверь, что есть **Sphere Collider** (добавляется автоматически).
5.  Add Component → добавь `ItemPickup`
    (namespace `NAV.Gameplay.Items`).
6.  В поле **Definition** перетащи ассет
    `Assets/NAV/ScriptableObjects/Items/Wood.asset`.
7.  В поле **Quantity** укажи, например, `5`.

### 7.4. Проверка

1.  Нажми **Play**.
2.  Подойди к сфере `TestPickup_Wood`, наведи на неё камеру.
3.  В HUD должна появиться строка `Interact: Pick up Wood`.
4.  Зажми **E** (удержание, как и раньше).
5.  Ожидаемый результат:
    -   сфера должна исчезнуть (если весь стак поместился в инвентарь);
    -   в Console — сообщение вида
        `Player picked up 5x Wood (now has 5).`;
    -   в HUD строка `Inventory: 1/20 slots used` (один слот занят
        деревом).
6.  Если инвентарь окажется полон (не в этом тесте, а в будущем) —
    сфера должна остаться на месте, а в Console появится сообщение
    `... inventory is full; could not pick up ...`.

Как и с кубом — `TestPickup_Wood` и `Wood.asset` можно оставить как
временный тестовый контент до появления настоящей системы добычи

5.  Нажми **I** ещё раз — панель должна закрыться, курсор снова

## Шаг 9. Новое: Gathering, инкремент 1 (ResourceNode)

Первый кусок Gathering (Фаза 3 из `DEVELOPMENT_ROADMAP_v0.1.md`) — узел
ресурса в мире, который можно "бить" несколько раз (E, как обычно),
пока он не даст ресурсы и не исчезнет. Я добавил:

-   `Assets/NAV/Scripts/Gameplay/Items/ResourceNodeDefinition.cs` —
    ScriptableObject-данные узла: какой предмет даёт, сколько за один
    удар, сколько ударов до истощения.
-   `Assets/NAV/Scripts/Gameplay/Items/ResourceNode.cs` — сам узел
    (реализует `IInteractable`, как `ItemPickup`). Каждый Interact() —
    один "удар": добавляет предметы в `PlayerInventory`, уменьшает
    счётчик оставшихся ударов, слегка уменьшает объект в размере
    (временная визуальная обратная связь) и при истощении уничтожает
    объект.

**Сознательно не сделано в этом инкременте** (по роадмапу это отдельные
пункты Gathering, не забытые): требование инструмента (топор/кирка —
пока нет системы Equipment), респавн/сохранение узлов (нужна система
Save), нормальные VFX/звук добычи.

### 9.1. Дать Unity перекомпилировать

Перейди в Unity, дождись компиляции, проверь Console на отсутствие
ошибок.

### 9.2. Создать тестовый ResourceNodeDefinition

1.  В окне **Project** перейди в `Assets/NAV/ScriptableObjects/Items/`.
2.  Правой кнопкой → **Create → NAV → Items → Resource Node Definition**.
3.  Назови ассет `TreeWoodNode`.
4.  В Inspector заполни:
    -   **Display Name** — `Tree` (необязательно, если оставить пустым —

    -   **Drop Item** — перетащи `Assets/NAV/ScriptableObjects/Items/Wood.asset`.
    -   **Amount Per Hit** — `1`.

### 9.3. Создать тестовый объект узла в сцене

1.  В Hierarchy: правой кнопкой → **3D Object → Cylinder** (чтобы

3.  Поставь рядом с игроком, например `Position: (0, 1, -3)`.

5.  Add Component → добавь `ResourceNode`

### 9.4. Проверка

## Шаг 12. Инвентарь: перекладка панелей, drag-and-drop, вес, выброс предметов, физика

По твоей просьбе (5 пунктов) я переработал инвентарь и панель крафта:

1.  **Панели больше не полноэкранные и не закрывают друг друга.**
    Inventory (**I**) теперь прижат к левому краю экрана, Crafting
    (**K**) — к правому; оба можно держать открытыми одновременно,
    персонаж по центру экрана ничем не закрыт. Курсор
    блокируется/разблокируется теперь централизованно в
    `PlayerInputHandler` (по счётчику открытых панелей), а не в каждой
    панели по отдельности — иначе закрытие одной панели при открытой
    второй ошибочно снова блокировало бы курсор.
2.  **Перетаскивание предметов внутри инвентаря.** Зажми ЛКМ на
    занятом слоте и перетащи на другой слот — предметы поменяются
    местами (если разные) или сложатся в один стак (если одинаковые и
    есть место).
3.  **Вес предметов.** У `ItemDefinition` уже было поле **Weight**
    (кг) — теперь оно реально используется. `PlayerInventory` получил
    поле **Max Weight** (по умолчанию `400`). В панели инвентаря
    появилась строка `Weight: X/400 kg`. Пока суммарный вес меньше
    лимита — всё как обычно; когда вес доходит до лимита (взять
    больше нельзя — `AddItem` сам это ограничивает), персонаж считается
    **перегруженным**: скорость ходьбы падает (множитель `Overload
    Speed Multiplier` на `PlayerMovementStats`, по умолчанию `0.5`), и
    стамина медленно тратится даже стоя на месте (`Overload Drain Per
    Second` на `PlayerStaminaStats`, по умолчанию `5`/сек), пока вес не
    станет меньше лимита.
4.  **Выброс предметов.** Перетащи предмет из инвентаря за пределы
    панели (в игровой мир) и отпусти ЛКМ — предмет выбросится перед
    персонажем как обычный подбираемый предмет.
5.  **Физика предметов.** `ItemPickup` теперь всегда требует
    `Rigidbody` (масса берётся из `Weight` предмета) — и выброшенные, и
    уже существующие в сцене предметы (например, `TestPickup_Wood`)
    падают под гравитацией и физически взаимодействуют с миром, а не
    висят в воздухе.

Для (4) нужен способ создать предмет в мире из чистого кода — для
этого у `ItemDefinition` появилось новое поле **World Prefab**: префаб,
который выбрасывается/спавнится (должен содержать компонент
`ItemPickup`). Без этого поля `DropItem` просто напишет ошибку в
Console и ничего не выбросит — это осознанное решение (см. правило
"Error Handling" в `CLAUDE.md`: не глотать ошибку молча), а не баг.

## Шаг 3. Подключить PlayerInteractor к отладочному HUD

1.  На объекте **Player** найди компонент `PlayerDebugHud`.
2.  В поле **Interactor** перетащи тот же объект **Player** (тот, на
    который в Шаге 2 добавлен `PlayerInteractor`).

Это добавит в HUD (F1 — показать/скрыть) строку `Interact: ...`,
показывающую подсказку текущего объекта, на который смотрит камера.

## Шаг 4. Создать тестовый объект для проверки (DebugInteractable)

1.  В Hierarchy: правой кнопкой → **3D Object → Cube**.
2.  Переименуй куб в `TestInteractable`.
3.  Поставь его в паре метров перед точкой старта игрока, на уровне
    земли (например, `Position: (3, 0.5, 3)`), чтобы в него можно было
    посмотреть камерой.
4.  Убедись, что на кубе есть компонент **Box Collider** (Unity
    добавляет его автоматически при создании Cube — просто проверь, что
    он не был случайно удалён).
5.  Add Component → добавь `DebugInteractable` (namespace
    `NAV.Gameplay.Interaction`).
6.  Поле **Prompt** можно оставить как `Interact` или написать что-то
    своё, например `Нажми E`.

## Шаг 5. Проверка (playtest)

1.  Нажми **Play**.
2.  Наведи камеру (мышью) на куб `TestInteractable`, подойди на
    расстояние взаимодействия (по умолчанию 3 метра).
3.  В HUD (левый верхний угол, если скрыт — нажми F1) должна появиться
    строка `Interact: Interact` (или твой текст из Prompt).
4.  Зажми клавишу **E** (действие Interact в проекте настроено как
    "Hold" — то есть нужно **удерживать**, а не просто нажать один раз;
    примерно 0.4 секунды).
5.  Ожидаемый результат:
    -   куб должен поменять цвет (по умолчанию — на зелёный);
    -   в окне **Console** должно появиться сообщение вида
        `TestInteractable was interacted with by Player.`
6.  Отойди от куба или отверни камеру — строка `Interact: ...` в HUD
    должна пропасть (замениться на `Interact: -`).
7.  Ещё раз удержи E, глядя на куб — цвет должен переключиться обратно.

Если что-то из этого не работает — опиши мне, что именно (что видно в
HUD, что в Console, на каком шаге не совпало с ожиданием), и я
разберусь.
